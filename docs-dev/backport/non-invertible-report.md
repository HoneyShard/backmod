## Worked Examples

- `Minecraft.setScreenAndShow` already exists in 26.1.2, so upstream's forward redirect from `setScreen` needs no inverse. A 26.2 mod calling it loads unchanged.
- `Gui.setScreen(Screen)` is new in 26.2 (`NO_COUNTERPART`). A backport would need a bridge that forwards to `Minecraft.setScreen`, which is a likely fix and is not verified. This is polyfill work, not a rename.
- `LevelRenderer.renderLevel` (26.1.2) became `render` (26.2) and dropped its trailing `ChunkSectionsToRender` parameter. The name and the descriptor both changed, so the differ lists 26.2's `render` as `NO_COUNTERPART` instead of linking the two. Upstream's forward shim registers a name-only rename for it, which would leave the extra argument missing in a call.
- Descriptor-only pairings are unsafe: the review file pairs `GlBuffer.close` with `checkCanBeUsed` and `Gui.tick` with `setClientLevelTeardownInProgress`.

## Limits

- Only `net/minecraft/` and `com/mojang/` are compared. Libraries such as `org.joml` or `com.mojang.serialization` that Minecraft bundles are out of scope.
- Supertypes outside the game jar (for example `java.lang.AutoCloseable`) are not followed, so a method a class gained from a JDK interface shows as `NO_COUNTERPART`.
- Private members are skipped. Mixins that target them are handled in the mixin step, not here.
- A member whose name and descriptor both changed is never paired, so it shows as `NO_COUNTERPART`. Some of the 998 rows are such pairs.
- Behavior changes with an unchanged signature are invisible to a jar diff.
- Full rows: `non-invertible.tsv` (this directory).
